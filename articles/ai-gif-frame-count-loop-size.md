画像生成AIに GIF アニメを直接書き出させる機能が出てきました。2026年11月4日に OpenAI が公開した Images 2.6 は GIF で動きを付けられ、同じモデル（GPT Image 2.6）は AI 動画サービスの DomoAI でも、コマ数と1コマの表示時間を数字で決めて書き出せます。

この記事は、Web 制作で「動くもの」を扱うエンジニア・制作者向けです。筆者が GPT Image 2.6 でスタンプ・ベル・ローディング・ボタン・SVG アイコンを作ってみて、**うまくいった条件と、外した条件**を中心にまとめます。

先に結論です。

- コマ数は「動き1周」で割り切れる数にする。点8個のローディングは 8 コマで1周し、12 コマでは位置が飛んだ
- AI の GIF は 720px 四方で、3DCG 風のキャラは1本 300〜450KB。Web に置くなら縮めるか、動画の形式（WebM）に変える
- ローディングやボタンの光は CSS のほうが軽くて直しやすい。AI の GIF は「CSS では描けない絵が動くもの」に使う

## なぜ GIF を AI に作らせたかったか

ここで扱うのは、チャットのスタンプや、立体感のある動くアイコンのような短いループです。これまでは、動画を作ってから GIF に変換するか、コマを1枚ずつ描くしかありませんでした。

GPT Image 2.6 の GIF 出力なら、文章で「何がどう動くか」を伝えるだけでコマのそろった GIF が返ってきます。一方で、Web の部品として見ると気になる点が3つありました。

1. ループがきれいにつながるか（最後のコマが最初に戻るか）
2. 全コマでキャラや文字の形が崩れないか
3. 容量が Web に置ける大きさか

以下、この3つを順に見ていきます。

## 設定できる値と、実際に出てきたもの

3つを確かめる前に、DomoAI の画像編集（Image Editing）で GPT Image 2.6 を選んだときに決められる値を整理します。GIF と SVG を選べたのは GPT Image 2.6 の Sunburst と Flare だけで、ほかのモデルでは選べませんでした（2026年11月20日時点）。

| 項目 | 選べる範囲 | 試して分かったこと |
|---|---|---|
| コマ数 | 2〜16枚（既定は9） | 動きの単位と合わないとループが飛ぶ |
| 1コマの表示時間 | 20〜2,000ミリ秒・10ミリ秒きざみ（既定は240） | 指定した値が全コマに同じく入った |
| 背景 | 透過・不透明・自動 | 透過の縁は1ビット（後述） |
| 解像度 | 2K・4K | 2K でも GIF は正方形 720×720、横長 960×528 で出た |
| 参照画像 | 16枚まで | 1枚渡すだけで顔と服が保たれた |

かかったクレジットは、8コマで12、10コマと12コマで20、8コマに参照画像1枚を足して14、SVG 1枚で30でした。生成前の見積もりと、生成後の残高の差で確かめた値です。料金は変わることがあるので、作る前に画面の見積もりを見てください。

筆者は Claude Code から DomoAI を呼ぶ MCP（AI から外のサービスを呼ぶための仕組み）で作りました。

## ループ：コマ数は「動き1周」で割り切る

ここからが本題の1つ目、ループのつながりです。いちばん差が出たのは、点8個が1つずつ光るローディングでした。

最初は 12 コマで頼みました。すると Sunburst でも Flare でも点の位置が飛び、1周半で終わって最後のコマが最初につながりませんでした。点は8個なのに、コマは12枚です。1コマに1つずつ進めると、12コマ目は1周を越えてしまいます。

そこでコマ数を 8 にし、1コマ目と8コマ目の状態を文章で書き足しました。

```text
Frame 1: the top dot is blue. Each next frame moves the blue dot one position clockwise, so frame 8 has the top-left dot blue and the loop returns to frame 1.
```

これで点が1つずつ時計回りに進み、きれいな1周になりました。この経験から、筆者はコマ数を次のように決めています。

- 点や目盛りのように数えられる動き＝その数と同じコマ数にする
- 往復する動き（揺れ・首振り）＝偶数にする
- 手を振るような自然な動き＝8〜10コマで十分なめらかに見えた

手を振るスタンプ（10コマ・1コマ120ミリ秒）は、最後のコマで手が少し上がったまま終わり、1コマ目に戻るときにわずかに跳びました。スタンプとしては気になりませんが、継ぎ目まで消したいなら、最後のコマの手の位置まで文章で指定します。

## 一貫性：変えないものと動かすものを分けて書く

ループがつながっても、コマごとにキャラの顔が変わっては使えません。この点は、プロンプトに「全コマで同じにするもの」と「動いてよいもの」を分けて書くことで安定しました。

手を振るスタンプでは「顔・髪・服・色・大きさは全コマで同じ、動くのは腕と首の傾きだけ」と書き、10コマとも腕と首以外は変わりませんでした。

同じキャラで別の動きを作るときは、1本目の1コマ目を参照画像にして「顔・髪・めがね・服・色だけ使う」と書きました。ジャンプする 8 コマの GIF は、めがねや前髪、パーカーのひもまで残っていました。ただし、1本目で抱えていたノートパソコンは消えました。「使うもの」に書かなかったものは引き継がれないので、残したい持ち物は名前を挙げます。

文字も試しました。「無料で試す」と書いたボタンに光を走らせる 12 コマの GIF では、日本語の文字が12コマとも同じ形で残りました。一方で、「光が1回走ったら少し止まる」という指示は守られず、1周の中で光が2回走りました。文字の形は守られても、時間の指示は守られにくいようです。

画風について1つ失敗がありました。参考にしたい作品のキャラの髪型や服の色まで書き写したところ、参考とほとんど同じ見た目の子が出てきました。「つやのある 3DCG のアニメ映画風」のように画風の言葉だけを残し、髪型や色は自分で決めて作り直しています。「既存のキャラに似せない」という一文も入れましたが、参考の色や服を書かないことのほうが効きました。

## 容量：GIF のままだと Web には重い

見た目が整ったところで、3つ目の容量です。AI が書き出す GIF は 720px 四方なので、そのまま置くと重くなります。ffmpeg で、同じ大きさの WebM（VP9 という圧縮方式の動画・透過あり）と、幅 240px に縮めた GIF に変えて比べました。

| 作例 | 元の GIF | WebM（同じ大きさ） | GIF（幅240px） |
|---|---|---|---|
| 手を振るキャラ（3DCG・10コマ） | 452KB | 125KB | 123KB |
| ジャンプするキャラ（3DCG・8コマ） | 311KB | 100KB | 85KB |
| 通知ベル（3DCG・8コマ） | 226KB | 62KB | 91KB |
| ボタン（12コマ・960×528） | 245KB | 42KB | 77KB |
| ローディング（8コマ） | 40KB | 24KB | 18KB |

キャラ・ベル・ボタンは、大きさを変えずに WebM にするだけで元の3分の1〜6分の1になりました。表示を大きく見せたい場所では動画の形式が向いています。ただし、透過付きの WebM はブラウザによって扱いが分かれるので、Safari でも表示を確かめてください。スタンプのように小さく出すなら、GIF のまま表示サイズまで縮めるのが手軽です。

絵柄でも容量は変わります。同じ揺れる通知ベルを、3DCG 風で作ると 226KB、太い線の平面のイラストで作ると 78KB でした。色の階調が多い絵ほど GIF は重くなるので、小さく置くアイコンは平面の絵柄で頼むのも手です。

## SVG 出力はそのまま部品にできた

容量の話の続きで、いちばん軽かったのが SVG です。GPT Image 2.6 の SVG 出力は、画像を埋め込んだだけのものではなく、path と circle で描かれたベクターでした。ショッピングカートの線のアイコンは 470 バイトでした。

色・線の太さ・角の丸めは、一番外の `<svg>` 要素の属性にまとめて書かれていました。そのため、使うときに直すのは外側の属性だけで済みます。

次は、出力の外側の属性のうち width・height・stroke を書き換えた形です（出力は width="2048" height="2048" stroke="#1E293B"）。

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 2048 2048"
     fill="none" stroke="currentColor" stroke-width="96"
     stroke-linecap="round" stroke-linejoin="round"
     width="24" height="24">
  <!-- 中の path と circle は出力のまま -->
</svg>
```

viewBox（SVG の中の座標の範囲）が 2048 四方と大きいので、width と height を表示したい大きさに書き換えます。線の太さ 96 は 2048 四方に対する値なので、24px で出すと約 1px の線になります。細すぎると感じたら stroke-width を上げます。stroke を `currentColor` にしておくと、まわりの文字色に合わせて色が変わります。

なお、SVG はテキストからだけ作れて、参照画像は渡せませんでした。コマのある動きにもならないので、動かすなら書き出した SVG に CSS のアニメーションを足します。

## うまくいかないとき

ここまでの試行で引っかかった点を、症状ごとにまとめます。

| 症状 | 原因 | 直し方 |
|---|---|---|
| ループの最後で位置が飛ぶ | コマ数が動きの単位で割り切れない | 点の数・往復の回数で割り切れるコマ数にし、1コマ目と最後のコマの状態を書く |
| 左右の揺れの幅がそろわない（ベルは左に大きく右に小さく揺れた） | 振れ方をコマごとに指定していない | 「1〜4コマで右へ、5〜8コマで左へ」のようにコマ番号で書く（ベルでは未確認。ローディングではコマ番号の書き方が効いた） |
| 参照画像の持ち物が消える | 「使うもの」に挙げていない | 残したい物を名前で書く |
| 暗い背景で縁がギザギザ | GIF の透過は1ビット（完全に透明か不透明かの2択）で、半透明の縁を表せない | 背景を不透明にして置く場所の色で作るか、透過付きの動画にする |
| 「少し止まる」が守られない | 時間の指示は守られにくい | 何本か作って選ぶ（止めたいコマをコマ番号で書く方法は、まだ試していない） |
| 参考作品とそっくりになる | 参考の髪型・服・色を書き写した | 画風の言葉だけ残し、見た目の要素は自分で決める |

## まとめ：CSS とどう分けるか

最後に、試してみて決めた使い分けです。

- **AI の GIF に任せる**：キャラのスタンプ、3DCG 風の動くアイコンなど、CSS では描けない絵が動くもの
- **CSS で作る**：ローディング、ボタンの光など形が単純な動き。数行で書けて、色も速さも後から変えられ、ボタンなら文字を選んだり翻訳したりもできる
- **AI の GIF を代わりに使う**：メールのお知らせや SNS の画像など、CSS を入れられない場所
- **AI の SVG を下書きにする**：静止したアイコン。外側の属性を直すだけで部品になる

最初の1本は、手を振るような単純な動きを 8〜10 コマで作り、コマを1枚ずつ見て最後が最初につながるかを確かめるのがおすすめです。そのあと容量を見て、縮めるか WebM に変えるかを決めます。
