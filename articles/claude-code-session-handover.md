## はじめに

Claude Code は、会話を閉じると前の話を覚えていません。`/clear` したとき、アプリを閉じたとき、会話が長くなって新しく開き直したとき、次の会話は「前回どこまでやったか」を知らない状態から始まります。

そこで多くの人が、`HANDOVER.md` や `task.md` のような**引き継ぎのメモ**を書かせます。筆者もそうしました。ところが、書かせ続けるうちに、引き継ぎのメモそのものが原因の失敗が起きるようになりました。

この記事は、ひとりで複数のサイトとツールを Claude Code で回している筆者が、引き継ぎのメモを何度か作り直してたどり着いた書き方の記録です。

- 対象読者：Claude Code で数日〜数週間かかる作業をしていて、引き継ぎのメモを書かせている（または書かせたい）人
- 結論：**引き継ぎには「途中のもの」だけを書く。状態（済んだ・まだ）は1か所にしか書かない。数字は書き写さず、正本の場所を書く**

運用の全体像（定期実行・完了報告・見張り役・フック）は前の記事に書きました。この記事はその中の「会話をまたぐ記憶」を深くしたものです。

https://zenn.dev/orectic/articles/claude-code-ai-org-daily-operations

## まず、何が起きたか

いちばん痛かった失敗から書きます。

あるプロジェクトの引き継ぎのメモ（`task.md`）は、使い始めて数か月で **1,630行**になっていました。中身の約45%は、もう**済んだ作業の記録**でした。済んだ作業も「あとで参考になるかも」と残していたからです。

その状態で、1つの会話の中で、**済んだ仕事を「残っている仕事」として3回報告**しました。

| Claude の報告 | 実際 |
|---|---|
| 書き直しが済んでいない記事が63件ある | 0件（全部済んでいた） |
| 人間の作業待ちが6件ある | 5件はもう済んでいた |
| 人間の判断待ちが4件ある | 3件はもう決まっていた |

原因は単純でした。1つの項目の状態が、**見出しの絵文字・目次の表・本文・外の台帳**の4か所に書かれていて、済んだときに1か所だけ直されていたのです。Claude はメモの古いほうの旗を読み、「まだ」と報告していました。

Claude が賢くても、メモが食い違っていれば間違えます。ここから、メモの書き方を変えました。

## 決めたこと1：メモを3つに分ける

1つのファイルに全部を書くのをやめ、役割で分けました。

| ファイル | 役割 | 書くもの |
|---|---|---|
| `MEMORY.md`（索引） | 会話の始まりに必ず読まれる目次 | ほかのファイルへのリンクと、1行の説明だけ（1行150字まで） |
| `HANDOVER.md`（引き継ぎ） | いま何が途中か | 途中の作業・次に手を動かすこと・待っているもの |
| `feedback_*.md`・`project_*.md` など（個別） | 変わらない知識 | 人間に言われた決まり・仕様・外のサービスの場所 |

Claude Code は、プロジェクトのメモのフォルダにある `MEMORY.md` を会話の始まりに読み込みます。そこで、`MEMORY.md` の**いちばん上に引き継ぎの行を固定**し、毎回最初に読まれるようにしています。

```markdown
- [引き継ぎ](HANDOVER.md) — いま途中のもの。会話の最初に必ず読む
- [短縮URLの決まり](feedback_short_links.md) — SNS に貼る URL は自社の短縮 URL にする
- [本番の場所](reference_hosting.md) — サーバー・デプロイの手順
```

分けた理由は、**変わるもの（状態）と変わらないもの（知識）を混ぜない**ためです。混ぜると、知識を足すたびに状態のファイルが太り、状態を直すたびに知識の行を消しそうになります。

ここまでで「どこに書くか」は決まりました。次は「何を書かないか」です。

## 決めたこと2：引き継ぎには「途中のもの」だけ書く

`HANDOVER.md` に書くのは、次の会話がすぐ手を動かせるための情報だけです。

```markdown
# 引き継ぎ（最終更新 2026-11-14 18:20）

## 途中のもの
- 記事の下書き：本文はできた。画像の差し替えが残り（articles/xxx.md の 3枚目）
- 本番の反映：人間の OK 待ち（選択式で聞いた。答えが来たら deploy）

## 待っているもの
- 外の審査：結果は管理画面で見る（数字はここに書かない）
```

逆に、次のものは書きません。

- **済んだ作業**：済んだら行ごと消す。経緯を残したいときは、別の `archive_2026-11.md` に移し、冒頭に「当時の記録。判断に使わない」と書く
- **普通に済んだ作業の報告**：途中で止まらずに終わったなら、引き継ぐものは無い
- **決定**：「この方針でいく」と決まったことは、作業の記録の中に埋めない（次の節）

1,630行の失敗は、「済んだもの」を残したことから始まっていました。**消す勇気**がいちばん効きました。

## 決めたこと3：状態は1か所、決定は別の台帳

それでも、長く続くプロジェクトでは、項目が数十件になります。そのときは、さらに状態と決定を切り出します。

| ファイル | 書くもの | 形 |
|---|---|---|
| `OPEN.md` | 開いている項目の**状態の唯一の正本** | 1項目1行：件名／担当／期日／**済んだと判定する方法** |
| `DECISIONS.md` | 人間が決めたこと | 1決定1行・新しい順・「もう一度提案してよいか」の列 |
| `task.md` | 開いている項目の背景・手順 | 状態は書かない |

```markdown
<!-- OPEN.md -->
| ID | 件名 | 担当 | 期日 | 済んだと判定する方法 |
|---|---|---|---|---|
| B-92 | 広告の停止テストの判定 | Claude | 12-05 | 期間の数字を出し、人間が続ける／やめるを選んだ |
```

大事なのは2つです。

- **「済んだと判定する方法」が書けない項目は登録しない**：「改善する」「様子を見る」のような項目は、いつまでも閉じられず、残り続けて旗が古くなります
- **決定に「もう一度提案してよいか」を持たせる**：人間が一度断った案を、次の会話がまた提案してくることがありました。断った理由と「再提案しない」を1行で残すと止まります

状態を2か所以上に書かない、を守るために、目次の表もやめました。目次の表が、別の場所に状態を持ってしまうからです。

ここまでで、メモが食い違う原因はかなり減りました。残ったのは、数字の扱いです。

## 決めたこと4：数字は書き写さず、正本の場所を書く

引き継ぎのメモに「残り23件」「バージョン 1.4.2」「スコア 87」と書くと、その数字は**書いた瞬間から古くなります**。次の会話は、古い数字を今の数字として読みます。

```markdown
❌ 未送信の営業先は残り23件
✅ 未送信の営業先の数は sales/list.csv の status 列で数える
```

数字を知りたいときは、毎回正本を読みにいかせます。手間は少し増えますが、**古い数字で判断する失敗**は無くなりました。

## 決めたこと5：書くのは「区切り」のとき

いつ引き継ぎを書かせるかも決めています。

| とき | 書くか |
|---|---|
| 作業が途中で止まった・休憩する・人間の答えを待つ | 書く |
| 「次はこれをやる」と話して終わる | 書く |
| 作業が普通に済んで終わる | 書かない（残すと雑音になる） |
| 会話が長くなって、新しい会話に移る | 書いてから閉じる |

最後の行は、最近足しました。会話が長くなると、Claude が前のほうの話を取りこぼし始めます。そこで、作業の区切りで引き継ぎを書かせ、**新しい会話に移ってから続ける**ようにしています。引き継ぎがしっかりしていれば、新しい会話は数ファイル読むだけで続きから入れます。

また、引き継ぎのファイルを「引き継ぎなし」に丸ごと書き換えるのは禁止にしました。別の会話が同じファイルに書いた途中の作業まで消えるおそれがあるためです。済んだ行だけを消します。

## 読ませるところまで仕組みにする

書き方を整えても、**次の会話が読まなければ意味がありません**。実際に、別のフォルダで開いた会話に仕事を頼んだら、そのプロジェクトのメモを読まずに作業を始め、決まりに反する投稿をしたことがありました。

そこで、Claude Code の hooks で2つを組にしています。

- 会話の始まり（SessionStart）：作業フォルダから「先に読むファイル」の一覧を作り、会話の頭に差し込む
- 最初の書き換えや push の前（PreToolUse）：会話の記録にその一覧を読んだ跡があるかを見て、無ければ止める

フックの中身は、別の記事に書きました。

https://zenn.dev/orectic/articles/claude-code-hooks-guard-examples

## うまくいかないとき

引き継ぎを運用していて、よく出た症状と直し方です。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 済んだ仕事を「残り」と報告する | 状態が2か所以上に書かれている | 状態の正本を1つ決め、ほかの場所の旗を消す |
| 一度断った案をまた提案される | 決定が作業の記録に埋もれている | 決定の台帳に1行足し、「再提案しない」を書く |
| 古い数字で判断する | 数字を書き写している | 正本の場所だけ書く |
| `[[リンク]]` が切れていく | ファイル名とメモの中の `name:` が食い違っている | `name:` をファイル名（拡張子なし）とそろえる。筆者のメモでは、これで58か所が切れていた |
| 引き継ぎのファイルが太り続ける | 済んだものを消していない | 済んだら行を消す。800行を超えたら状態と決定を切り出す |
| 次の会話が引き継ぎを読まない | 読む場所が決まっていない | `MEMORY.md` の一番上に固定する。それでも読まないなら hooks で止める |

## これから始めるなら

1. `MEMORY.md` を作り、一番上に `HANDOVER.md` の行を置く
2. `HANDOVER.md` には「途中のもの」と「待っているもの」だけを書かせる
3. 済んだら消す。決定は別の行に1行で残す
4. 数字は書き写さず、正本の場所を書く
5. 項目が数十件になったら、状態（`OPEN.md`）と決定（`DECISIONS.md`）を切り出す

メモは、増やすより**消すほうが難しい**ものでした。引き継ぎのメモが短いうちは、次の会話も迷いません。
