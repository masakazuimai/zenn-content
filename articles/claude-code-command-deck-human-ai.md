Claude Code を10個近いプロジェクトで並行して使うようになって、困ったことがひとつあります。**どのターミナルで何が動いていて、どれが自分の返事を待っているのかが分からない**ことです。

そこで、全プロジェクトの Claude Code を1画面で見渡して、指示もそこから投げられるローカルのダッシュボード「COMMAND DECK」を作りました。この記事では、作ったものよりも「**人間とAIで何をどう分け持つか**」をどう画面に落としたかを中心に書きます。

まだ作ったばかりの開発途中です。うまくいった設計と、まだ足りない部分の両方を正直に書きます。

## 前提：AIを「部下」として扱う運用体制

ダッシュボードの前に、運用の前提を書いておきます。私は Claude を次のような役割分担で動かしています。

| 役割 | 担当 | やること |
|---|---|---|
| CEO | 人間（私） | 方針の判断、優先順位、**公開ボタンを押す** |
| COO | メインの Claude | 実務の直接実行。執筆・実装・分析・デプロイ |
| 調査部 | サブエージェント | 既存記事の全件スキャンなど、大量に読む仕事 |
| 監査部 | サブエージェント | COO の成果物とルールの食い違いを検出する（修正はしない） |

ポイントは、**AIに渡すのは実行で、人間が持つのは判断と公開**という線引きです。この線をどこに引くかが決まっていないと、AIに任せる範囲を広げるほど不安が増えていきます。

この体制をどういう順番で作ったかは「[AI組織は組織図から作ると失敗する](https://codequest.work/ai-organization-build-order/?utm_source=zenn&utm_medium=article&utm_campaign=claude-code-command-deck-human-ai)」にまとめています。

ダッシュボードはこの線引きを「見える化」して、人間が判断に集中できるようにするための道具として作りました。

## 作ったもの：COMMAND DECK

画面は大きく4つの要素でできています。

1. **プロジェクトカード**：直近30日に Claude Code を使ったプロジェクトを自動で並べ、それぞれの状態を表示する
2. **指示ボックス**：カードを選んで指示を書くと、そのフォルダでバックグラウンドの Claude Code が起動する
3. **ストリーム**：直近に動いた会話の一覧（どのプロジェクトで何が走っているか）
4. **会話ビュー**：会話を別ウィンドウで開き、私の指示・Claude の返答・使ったツールだけを時系列で読む

技術的には Next.js のアプリで、Claude Code の CLI と会話ログを読んでいるだけです。ダッシュボード自身はデータベースを持たず、**状態を一切保存しません**。この理由は後で書きます。

## 設計1：状態は4つだけにする

カードに出す状態は4つに絞りました。

| 表示 | 意味 | 人間がやること |
|---|---|---|
| 作業中 | Claude が動いている | 何もしない |
| 返事待ち | Claude が確認を求めて止まっている | **答える** |
| 完了 | 終わった | 結果を読む |
| 待機 | 何も動いていない | 必要なら指示を出す |

1つのプロジェクトで複数の会話が走っていることもあります。そのときカードには「**一番手がかかる状態**」を出すようにしました。優先順位は「作業中 > 返事待ち > 完了 > 待機」です。

最初は細かい状態（ツール実行中、思考中など）も出そうとしましたが、やめました。**人間がダッシュボードを見て知りたいのは「自分が動く必要があるか」だけ**だからです。状態を増やすほど、見る側の判断が増えて疲れます。

## 設計2：AIに渡す権限と、人間が持つ権限

いちばん悩んだのがここです。指示ボックスから起動する Claude Code は、許可モードを `auto` にしています。いちいち確認ダイアログで止まると、外出中や就寝中に作業を投げても進まないからです。

その代わり、**取り返しのつかない操作は権限ではなくルールで縛る**ことにしました。

| 操作 | 誰が持つか | どう担保しているか |
|---|---|---|
| 調査・分析・下書き作成 | AI | 自由にやってよい |
| コード修正・コミット | AI | ルールで手順を固定（レビュー・検証を挟む） |
| 記事の公開・メール送信・削除 | **人間** | 指示文に「公開しない／下書きまで」と書く。ルールファイルにも明記 |
| 決定事項の記録 | AI が書く、人間が決める | 「決定台帳」に1決定1行で残す |

ルールは各プロジェクトの `CLAUDE.md` とメモリファイルに書いてあり、どの会話の Claude も同じものを読みます。つまり**ダッシュボードは権限を管理せず、権限の線引きはプロジェクト側のルールが持つ**という分担です。

## 設計3：ダッシュボードは状態を持たない

COMMAND DECK から指示を出すと、毎回まっさらな新しい会話が立ち上がります。前の会話の記憶はありません。それでも作業が途切れないのは、**引き継ぎ情報をプロジェクト側のファイルに置いている**からです。

- 「いま開いている作業」は1ファイル（`OPEN.md` や `HANDOVER.md`）が唯一の正本
- 「人間が決めたこと」は決定台帳に日付つきで残す
- 新しい会話の Claude は、最初にこれらを読んでから動く

ダッシュボード側に状態を持たせると、プロジェクトのファイルとダッシュボードの二か所に状態ができて、必ずどちらかが古くなります。実際、引き継ぎファイルの見出しと本文が食い違って、**終わった作業を「残タスク」として報告される事故**が過去に何度もありました。

なので、ダッシュボードは Claude Code の CLI と会話ログを**読むだけ**にしています。正しい状態は常にプロジェクト側にある、という形です。

## 設計4：ローカル専用で、起動先はサーバーが決める

ブラウザから AI に作業を投げられる道具なので、守りは固めにしています。

- サーバーは `127.0.0.1` でだけ待ち受ける。スマホからも開けない
- API は `Host` と `Origin` がローカルのリクエストだけを通す（他のサイトからこっそり POST されるのを防ぐ）
- 起動先のフォルダは画面から受け取らない。サーバー側で持っているプロジェクト一覧から ID で引く
- Claude Code で「信頼済み」にしたフォルダにだけ指示を送れる

便利さのために外から触れるようにしたくなりますが、**指示を投げられる画面は、それ自体がAIへの入口**です。外に出すなら認証の設計から考え直す必要があるので、今は割り切っています。

## どう使うつもりか

今の機能（プロジェクトを選んで新しい指示を投げる／動いているか見る／会話を読む）で、まず試している使い方は次の3つです。

1. **朝の一斉点検**：各プロジェクトに「引き継ぎファイルを読んで、今日やることと止まっているものを3行で報告して。作業はまだしないで」と順に投げる。完了したカードから会話を開いて読む
2. **定型作業の投げ込み**：手順をスキル化してある作業（分析レポート、書式チェックなど）は指示1行で回るので、投げて別のことをする
3. **出かける前に重い作業を投げる**：全件スキャンのような時間のかかる調査を投げておき、戻ったら会話ビューで結果を読む

狙いは、ターミナルを何枚も開いて行き来せずに**全プロジェクトの現状を数分でそろえること**です。実際にどれだけ手間が減ったかは、しばらく運用してから数字で書くつもりです。

## まだ足りないもの

開発途中なので、足りないものもはっきりしています。次に足す予定の機能を優先順に並べます。

| 順 | 機能 | 足りないと何が困るか |
|---|---|---|
| 1 | 続きの指示（終わった会話への追加指示） | 「さっきの続きで直して」ができず、結局ターミナルに戻る |
| 2 | 返事待ちへの返答 | 確認を求めて止まった Claude に、画面から答えられない |
| 3 | 完了の通知 | 画面を見張っていないと終わったことに気づけない |
| 4 | 定型指示ボタン | 毎朝の点検指示を毎回打っている |
| 5 | 最後の返答をカードに表示 | 結論を読むために毎回会話を開いている |

特に1がないと「投げっぱなし」以上の使い方にならないので、ここから手を付けます。

## まとめ

- AIに複数プロジェクトを任せると、「**どこで何が動いて、どれが自分を待っているか**」が真っ先に見えなくなる
- ダッシュボードの状態は「人間が動く必要があるか」で4つに絞る
- 権限の線引きは画面ではなくプロジェクト側のルールに持たせ、**人間は判断と公開だけを握る**
- ダッシュボード自身は状態を持たず、読むだけにする。状態の正本は一か所にしかない
- 指示を投げられる画面はAIへの入口なので、ローカル専用から始める

AIに任せる範囲を広げるほど、人間に必要なのは「全部を見ること」ではなく「**自分が判断すべきところだけを見ること**」だと感じています。同じように Claude Code を何本も走らせている方の参考になればうれしいです。
