## 公開翌日に3〜5位に載った

個人開発でWeb系の小さなツールをいくつも作って公開しています。CSSジェネレーターとか、画像系とか、ブラウザで完結する単機能ツールです。

2026年6月、そのうちの1本（以下ツールB）が、**公開翌日にGoogle検索の3〜5位**に載りました。まぐれかと思ったら、同じ月に公開したツールAは初クリックまで4日・その後5〜8位に定着、ツールCもほぼ即日で6位前後に入りました。

一方で、**それより少し前に公開した3本のツールは、同じような作りなのに30日経っても1ページ目に定着していません**。

この差は何なのか。GSC（Google Search Console）の実測データで条件を分解してみたら、個人開発者がツールを公開するときに使える再現性のある知見になりそうだったので、まとめます。

## 前提：時期がGoogleのコアアップデートを挟んでいた

まず時系列です。[Google Search Status Dashboardの公式記録](https://status.search.google.com/products/rGHU1u87FJnkP6W2GwMi/history)によると：

- **2026年5月コアアップデート**: 5/21開始 → 6/2完了（11日21時間）
- **2026年6月スパムアップデート**: 6/24 → 6/26

そして手元のツールの公開時期と初速はこうでした。

| ツール | 公開 | 検索1ページ目到達 | 初速CTR |
|---|---|---|---|
| ツールA | アプデ完了の数日後 | 数日で5〜8位に定着 | 15〜30% |
| ツールB | 完了の約2週間後 | **公開翌日に3〜5位** | 17%〜（50%の日も） |
| ツールC | 完了の約3週間後 | ほぼ即日で6位前後 | 11〜16% |
| それ以前に公開した3本 | アプデ開始前 | 30日窓で1ページ目に定着せず | — |

アップデート後に公開した3本だけが即座に立ち上がり、前に公開した3本は立ち上がらない。サイト全体でもこの期間、検索クリックは前30日比で+86%、表示回数は+122%伸びています。

:::message
正直な注記：これは1サイト・少数ページの相関観測で、因果の証明ではありません。一部のツールは検索需要自体が伸びているテーマなので、需要側の追い風もあります。ただ「公開翌日に3〜5位」という順位の付き方は需要の大きさでは説明できないので、評価環境側の変化が効いていると解釈しています。
:::

## 発見1：ツールは記事より「初速」が明らかに速い

同じ時期に記事（ブログポスト）も公開していたので比較できました。

- **単体テーマの新規記事**: 順位は1週間ほどで1ページ目圏に付くが、**CTRは3〜5%**でクリックの立ち上がりが鈍い
- **ツール**: 1ページ目に載った瞬間から**CTR 15〜30%**

順位が付く速さはほぼ同じ。差が付いたのは**CTR（約3倍）**でした。

理由はシンプルだと思っています。「◯◯ ジェネレーター」「◯◯ ツール」と検索する人は、読み物ではなく**今すぐ使えるもの**を探している。ツールのタイトルはその意図に文字通り一致するので、同じ順位でも選ばれやすい。

つまり個人開発者にとってツールは、**単体で初速が出る資産**です。記事で同じことをやるには、先にサイト内にトピックの蓄積（クラスタ）が要ります。実際、既存の強いページ群にぶら下げて公開した記事は初日からクリックが出ましたが、単体テーマの記事は出ませんでした。

## 発見2：既存ページの回復は遅く、新規ページは速い

Google公式の[コアアップデート解説](https://developers.google.com/search/updates/core-updates)には、既存ページの大きな評価回復には「次のコアアップデートを待つ必要がある可能性」があると書かれています。

一方、新規ページは公開時点の評価環境でゼロから査定されます。既存ページの再評価が更新サイクルに縛られるのに対して、新規ページは待ち行列に並ばない。

アップデート完了直後は、いわば**査定基準が更新された直後の空いている審査窓口**で、そこに新しい基準を満たしたページを持ち込むと最速で通る——観測した挙動はそういう形をしていました。

## 公開前に入れた8項目

では「新しい基準を満たしたページ」とは何か。アップデート後に公開したツール3本に共通して入れていたのは、この8項目です。

### 土台（SEOの基本）4項目

1. **既存ページとの双方向内部リンク**（関連ツール一覧・記事からの導線）
2. **検索意図に一致するタイトル**（「無料」「ブラウザ完結」「登録不要」など、使えることが伝わる語）
3. **技術品質**：静的HTMLまたはSSRで、JSなしでも本文がクロール可能・表示速度・モバイル対応
4. **サイトマップ登録とインデックス送信**

3は特に重要です。SPA（CSR）で作るとGooglebotは読めてもAIクローラーには本文が見えない問題があります（[以前検証した記事](https://zenn.dev/orectic/articles/ai-crawler-spa-curl-check)）。

### 上乗せ（AI検索も意識した品質）4項目

5. **ファーストビューに直接回答**：「このツールは何ができるか」を最初の1画面で言い切る
6. **構造化データ**：ツールならWebApplication + FAQPage

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebApplication",
  "name": "無料ジェネレーター",
  "applicationCategory": "DeveloperApplication",
  "operatingSystem": "Web",
  "offers": { "@type": "Offer", "price": "0", "priceCurrency": "JPY" }
}
</script>
```

7. **著者情報と更新日の明示**（誰が作って、いつメンテしているか）
8. **llms.txtへの掲載**：サイト直下に置く、AI向けのサイト案内ファイル

```markdown
# サイト名

> サイトの一行説明

## ツール
- [無料ジェネレーター](https://example.com/tool/): CSSコードを生成できる無料ツール
```

5〜8はいわゆるAIO/GEO（AI検索に引用されるための）対策として入れたものですが、中身を見ると**Googleが品質評価に使うシグナルとほぼ同じ**です。実際、AI経由の流入（ChatGPT等からのリファラル）も4月比で約1.9倍になりました。ただし割合ではサイト全体の1〜3%台で、伸びの主役はあくまでGoogle検索側でした。

なお、この8項目のうち技術品質・構造化データ・著者情報（E-E-A-T）・llms.txtあたりは、拙作の無料SEO診断ツール[Direbase](https://seo.codequest.work/)でURLを入れるだけでまとめてチェックできます。公開前の最終確認に使ってください（この検証も同ツールの45項目をベースにしています）。

## まとめ：個人開発者向けの実務指針

- **ツールは単体で初速が出る**。新しい領域を攻めるなら、記事より先にツールで橋頭堡を作る方が速い
- **公開前に土台4項目＋上乗せ4項目を入れる**。公開後に足すのではなく、公開時点で両方入りにする（既存ページの再評価は次のアップデートまで待たされることがあるが、新規ページは即査定される）
- **コアアップデート直後は新規公開の好機かもしれない**。少なくとも手元の実測では、完了後に公開したページだけが翌日〜数日で1ページ目に載った
- **CTRを見る**。順位が付いてもクリックされないなら、タイトルが検索意図とズレている

SEO実務者向けの詳細な分析（全データの分解・言えないことの整理を含む）は、[Direbase](https://seo.codequest.work/)のラボ記事に書きました：

https://seo.codequest.work/ja/blog/seo-base-aio-overlay-report

ツールを作ったら、公開ボタンを押す前に8項目。それだけで立ち上がりがかなり変わる、というのが今回の実測の結論です。
