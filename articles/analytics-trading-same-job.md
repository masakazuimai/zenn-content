Webサイトのアクセス解析（アナリティクス）と、株のトレードシステム。私はこの2つを並行して運用していますが、あるとき「これは同じ仕事をしている」と気づきました。

結論から書きます。**どちらも「基準からのズレを数字で見つけて、小さく試して、決めた日に測り直す」仕事です。** 見ている対象が検索結果か株価かが違うだけで、判断の型はほぼ同じでした。

ちょうどトレード側で新しい検証を始めたところなので、この記事では共通点を整理したうえで、**判定日より前に「どう比べるか」を公開**しておきます。結果は判定日のあとに、ここで宣言した比べ方のまま書きます。

:::message
この記事は投資の勧誘を目的としたものではありません。個別銘柄は記号（銘柄A・銘柄Bなど）で表記し、売買を推奨するものではありません。
:::

## どちらも「中身の価値」は見ていない

最初は「アナリティクスもトレードも、情報を集めて価値を見極める仕事」だと思っていました。株でいえばファンダメンタル分析（業績や財務から企業の価値を測る方法）のイメージです。

ところが実際に自分のシステムを見直すと、どちらもそうなっていませんでした。

| | 見ているもの | 中身の価値を測っているか |
|---|---|---|
| アナリティクス | 表示回数・クリック率（CTR）・掲載順位といった**検索ユーザーの行動データ** | 測っていない |
| トレード | RSI（売られすぎ・買われすぎを示す指標）や移動平均といった**値動きの偏り** | 測っていない |

トレード側は決算の予定日を注意として画面に出していますが、売買の判断には使っていません。どちらも「良いもの」を探すのではなく、**「数字の出方がいつもと違うところ」を探している**。これが共通点の出発点でした。

## 共通点：判断の型が同じ

工程ごとに並べると、対応関係がはっきりします。

| 工程 | アナリティクス（SEO） | トレード |
|---|---|---|
| 基準を決める | 順位ごとの期待CTR（例：7〜10位なら2〜3%） | RSIの35（買い）と65（売り）、移動平均線 |
| ズレを探す | 表示は多いのに、期待CTRを下回っているページ | RSIが35を下回った、売られすぎの銘柄 |
| 対象を絞る | 表示回数50以上・順位20位以内・1回5記事まで | 売買代金の上位60銘柄・1枠の予算内の価格 |
| 小さく試す | 1記事につき変更は1回だけ | ルールを1つずつ変えた台帳を並べて動かす |
| 測り直す | 変更から3週間後に同じ指標を再計測 | 決めた判定日に成績を並べる |
| 環境が急に変わる | Googleのコアアップデート | 相場の局面の転換 |

特に似ているのが「基準」の置き方です。SEOでは、CTRが3%と聞いても良いのか悪いのかは分かりません。1位なら低すぎますし、10位なら十分です。**絶対値ではなく、条件ごとの基準と比べて初めて判断できる**。RSIも同じで、数値そのものではなく「35を割ったか」という基準との位置関係で判断します。

## 決定的な違い3つ

型は同じでも、市場としての性質は大きく違います。

1. **結果を自分で動かせるか**
   SEOはタイトルや本文を書き換えれば結果が変わります。株価は自分の注文ではまず動きません。SEOは「相場を読む」だけでなく、自分が打ち手を持っている市場です。
2. **相手がいる取り合いか**
   トレードは誰かの損が誰かの得になる取り合いで、見つけた優位性は他の参加者も見つけるので薄れていきます。SEOのニッチなキーワードは、気づいた人が少なければ優位性が長く残ります。
3. **外れたときの損の形**
   SEOの施策が外れても失うのは時間だけです。トレードの外れは資金の減少として直接表れます。

型が同じなら、**検証の仕組みはお互いに持ち寄れる**はずです。そこで、検証の設計がより厳密に組めるトレード側で、その仕組みを先に試すことにしました。

## トレード側の検証設計：8本の台帳を並べる

トレードシステムでは、毎営業日16時に終値でシグナルを判定し、**ルールを少しずつ変えた8本のペーパートレード（仮想売買）の台帳**を同時に記録しています。

| 台帳 | 内容 | 比べたいこと |
|---|---|---|
| ①基本 | 9年分の過去データで検証済みのルールをそのまま回す | **対照群**（すべての比較の基準） |
| ②旧実弾 | 以前の実際の売買で使っていた条件で買う | 実際の売買の条件は良かったのか |
| ③業種上限 | ①に「同じ業種は2銘柄まで」を足す | 分散すると下落が浅くなるか |
| ④20日線利確 | ①に「20日移動平均を上回ったら利確」を足す | 早めの利確は得か |
| ⑤Claude | ⑥にClaude（AI）の判断の上乗せを加える | AIの裁量に価値はあるか |
| ⑥Claude自動 | Claudeが選んだルールの自動部分だけを回す | ⑤との差を測るための影の台帳 |
| ⑦分割 | 株式分割の発表直後に買い、権利落ちの前に売る | RSIとは別の売り方は効くか |
| ⑧強気 | ①の候補のうち、アナリストの評価が強気の銘柄だけ買う | 外部の評価で絞ると良くなるか |

設計で一番大事にしたのは、**①基本を対照群として必ず置くこと**です。何もしない比較相手がいないと、成績が良かったときに「ルールが効いた」のか「相場全体が上がっただけ」なのかを区別できません。

⑤と⑥の組み合わせも同じ考え方です。AIに売買の判断を任せた台帳だけを見ても、AIの判断が効いたのか、AIが最初に選んだルールが効いたのかが分かりません。**AIの上乗せを入れない影の台帳を並走させ、その差だけをAIの価値として測ります。**

## 比べ方の公開（判定は2026年11月中旬）

ここが本題です。判定の前に、比べ方を次のとおり公開します。

1. **基準は①基本**。②〜⑥は①と並べて比べる
2. **比べる範囲は2026年9月25日以降に買いを決めた分だけ**。⑧強気は売買を始めた2026年10月13日以降の分
3. **指標は1件あたりの騰落率**。判定日に保有中のものは、その日の終値で評価する
4. **⑦分割**は対象の銘柄が他の台帳と違うため、1件あたりの騰落率そのものを見る
5. **台帳全体の損益の合計では比べない**

5つ目には理由があります。①基本は早く始めたため、比較の起点の時点で枠がすでに埋まっていました。後から始めた台帳と合計で比べると、スタートの位置が違うものを比べることになります。そこで、全台帳が同じ条件で買える日以降の「1件ごとの成績」にそろえました。

なお、「①を何ポイント上回れば有効」という合否の線はあえて置いていません。2か月弱の取引件数では、線を引いても偶然の範囲を出ない可能性が高いためです。今回公開するのは、**後から都合よく変えられない比べ方**のほうです。

## 始める前に捨てたもの

ペーパーで試す前に、9年分（2018〜2026年）の過去データでバックテストを重ね、効かないものを先に捨てました。

- **現行ルールの9年の姿**：7勝2敗・年平均およそ+10%・最大下落はおよそ-30%（2020年）。ただし現在上場している銘柄で検証しているため、途中で消えた銘柄が入らない「生存バイアス」があります
- **ルールの改善案28通り**：すべて現行ルールを上回れませんでした。相場全体の地合いで売買を止めるフィルターは逆効果でした
- **過去の成績で銘柄を選ぶ**：前半の成績と後半の成績にほぼ相関がなく、続きませんでした
- **損切りの幅を広げる**：広げるほど成績が悪化しました

効いたのは、銘柄そのものの選び方より**「どの範囲から選ぶか」**でした。売買代金の上位60銘柄・予算内の価格という範囲の作り方のほうが、個別の銘柄選びより結果を左右していました。

「効かなかった」を先に確定させておくと、ペーパーで何を比べるべきかが絞られます。8本の台帳は、バックテストで捨てきれなかった候補だけを残した結果です。

## SEOに持ち帰りたいもの

トレード側でこの設計を組んでみて、SEOの施策評価の弱点がはっきり見えました。

**SEOの施策評価には、対照群がありません。** タイトルを変えた記事の「変更前と変更後」を比べるだけなので、同じ時期にサイト全体のアクセスが増えていれば、施策の効果と区別がつきません。コアアップデートの期間をまたげば、なおさらです。

トレード側の設計を移すなら、次の3つになります。

| トレード側でやっていること | SEOでのやり方 |
|---|---|
| ①基本という対照群を置く | 施策をしない似た記事を「何もしない組」として一緒に計測する |
| 比べ方を先に公開する | 施策の前に「何をもって成功とするか」を1行書いておく |
| 範囲をそろえて1件ずつ比べる | コアアップデートの期間中に計測した結果は別扱いにする |

もうひとつ、トレードの「動く理由があるときだけ入る」という考え方も、SEOでそのまま当てはまりました。私のサイトでは、**検索されている語がタイトルに無かった記事**をその語に合わせて直したときは結果が動き、**語がすでに入っている記事**の文言を磨いただけのときはほとんど動きませんでした。理由のないエントリーが勝てないのと同じ形です。

## 判定日のあとに書くこと

2026年11月中旬の判定のあと、この記事で公開した比べ方のまま結果をまとめます。

- ②〜⑥が①基本を上回ったか、下回ったか
- AIの上乗せ（⑤と⑥の差）に価値はあったか
- 結果が良くても悪くても、比べ方は変えずに書く

①基本を上回る台帳がひとつも無かったとしても、それは「検証済みのルールが一番強かった」という結果です。どちらに転んでも記事として成り立つように、比べ方を先に出しました。

## まとめ

- アナリティクスとトレードは、どちらも**基準からのズレを数字で見つけ、小さく試し、決めた日に測り直す**仕事
- 両方とも中身の価値ではなく、**行動データや値動きの偏り**を見ている
- 違いは、結果を自分で動かせるか・取り合いか・外れたときの損の形
- 検証の仕組みは持ち寄れる。トレード側では**対照群を置き、比べ方を判定前に公開**した
- SEOの施策評価に足りないのは、対照群と事前の基準

数字を「絶対値ではなく条件ごとの基準と比べる」考え方は、アクセス解析のあらゆる指標に共通します。広告の直帰率を例にこの考え方を整理した記事を「[ディスプレイ広告の直帰率80%は正常なのか｜平均56.5%が使えない理由](https://codequest.work/display-ads-bounce-rate/?utm_source=zenn&utm_medium=article&utm_campaign=analytics-trading-same-job)」にまとめています。
