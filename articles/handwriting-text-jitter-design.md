ブラウザで動く手書き風文字ジェネレーターを作りました。入力した文章を手書きの書体で描き直して、画像として書き出すツールです。

作りはじめて最初に分かったのは、**手書き風のフォントを当てても手書きには見えない**ということでした。原因は書体ではなく、並び方にあります。

この記事は、その「並び方」をどう崩したかの設計メモです。

## 1文字ずつ乱数で回すと脅迫状になる

最初に試したのは素朴な方法です。文字ごとに乱数で回転と位置のズレを与える。

```js
// うまくいかなかった例
for (const ch of line) {
  const angle = (Math.random() - 0.5) * 0.1;
  const dy = (Math.random() - 0.5) * 6;
  drawGlyph(ch, x, baseY + dy, angle);
  x += advance;
}
```

出てきたのは手書きではなく、雑誌の切り抜きを貼り合わせた**脅迫状**でした。文字がそれぞれ勝手な方向を向いていて、行としてのまとまりがありません。

乱数の幅を小さくすると、今度は単にぼんやりした印刷物になります。大きくすれば脅迫状、小さくすれば印刷物。その間に手書きはありませんでした。

## 手書きの乱れには構造がある

罫線のない紙に文章を書いたときの、自分の字を思い出してみてください。

まず**行全体が斜めに流れます**。そして書き進むうちに、ゆるい波を描いて上下します。1字ごとのばらつきは、その流れの上に重なる細かい震えです。

つまり乱れは1層ではなく2層あり、しかも順番が決まっています。先に行の流れがあって、後から手の震えが乗る。1文字ずつの乱数だけで作ろうとしたのが間違いでした。

## 先に行の流れを決める

行ごとに「傾き」と「うねりの波」を持たせます。

```js
function lineFlow(rnd, tilt, wave, size) {
  return {
    slope: (rnd() - 0.5) * 2 * tilt,          // 行全体の傾き
    amp:   wave * size * (0.6 + rnd() * 0.8), // うねりの振幅
    len:   size * (4 + rnd() * 3),            // うねりの波長
    phase: rnd() * Math.PI * 2,               // 位相
  };
}
```

行頭からの距離 `t` を渡すと、基準線のズレを返す関数を用意します。

```js
function flowAt(f, t) {
  const k = 2 * Math.PI / f.len;
  const slopeTan = Math.tan(f.slope);

  // 基準線の縦ズレ
  const off = t * slopeTan + f.amp * Math.sin(k * t + f.phase);

  // 基準線の接線の角度（上式の微分の arctan）
  const ang = Math.atan(slopeTan + f.amp * k * Math.cos(k * t + f.phase));

  return { off, ang };
}
```

各文字は、自分の中心が行頭から `t` の位置にあるとして `flowAt(f, t)` を呼び、`off` の分だけ縦にずらして置きます。

## 一番効いたのは接線角のほう

ポイントは `off` ではなく `ang` です。

`off` だけを使って文字を上下させても、まだ手書きになりません。行はうねっているのに、**文字の軸が全部まっすぐ垂直のまま**だからです。うねった線の上に活字が整列している、という奇妙な絵になります。

`ang` は基準線の微分、つまり**その地点での接線の角度**です。これを文字の回転に足すと、行が上がっていく場所では文字も上を向き、下がる場所では寝ます。

```js
const fl = flowAt(f, t);
rotateGlyph(path, cx, cy, fl.ang + jitterAngle);
```

実際に手で書くとき、行が右上に流れれば手首の角度も一緒に傾きます。この1行を入れた瞬間に、絵が手書きになりました。

そのうえで、字ごとの微揺れ（傾き・位置・大きさ）を少しだけ足します。**配分が逆になると台無し**で、字ごとの揺らぎを大きくすると行の流れがその中に埋もれて、また脅迫状の方向へ戻ります。行の流れが主、字ごとの震えが従です。

## シードを固定しても崩れないようにする

揺らぎは `Math.random()` ではなく、シードから決まる疑似乱数（mulberry32）で作っています。番号を控えておけば、気に入った崩れ方をあとから呼び戻せるからです。

ところが、素直に書くと落とし穴があります。空白文字を単に読み飛ばす実装にすると、**文中にスペースを1つ足しただけで、それ以降の文字の揺らぎが全部入れ替わります**。乱数列を消費する位置がずれるからです。

文章を少し直すたびに全体の表情が変わるのでは、シードで再現できる意味がありません。

対処は単純で、描かない文字でも乱数を同じ回数だけ空回しします。この実装では1文字が消費する乱数はちょうど6個（傾き・拡縮・位置x・位置y・線幅のムラ・濃さのムラ）でした。

```js
if (ch === " " || ch === "　") {
  // 描画はしないが、乱数列の位置だけ進めておく
  rnd(); rnd(); rnd(); rnd(); rnd(); rnd();
  continue;
}
```

地味ですが、「シードで再現できる」が実用になったのはこの手当てを入れてからでした。

## かすれを網点に見せない

鉛筆を選んだときの「かすれ」は、文字を描いたレイヤーをノイズで削って作ります（`destination-out` で合成）。

最初は一様乱数で削りました。結果は、かすれではなく**印刷の網点**です。抜けた粒が画面全体に均等に散らばってしまい、紙の凹凸でインクが乗らなかった感じになりません。

実際のかすれは、点が均等に抜けるのではなく、**ある区間だけまとめて乗りが悪くなる**形で出ます。そこで、粗い濃淡のむらを先に作り、その値で「削る確率」を場所ごとに変調しました。

```js
const cell = 26;  // 濃淡フィールドの粒。描画ブロックより十分大きくする
const fw = Math.ceil(w / cell) + 1;
const fh = Math.ceil(h / cell) + 1;
const field = new Float32Array(fw * fh);
for (let i = 0; i < field.length; i++) field[i] = rnd();

// 削るかどうかを、その場所の濃淡 f で変調する
const f = field[fy * fw + Math.floor(x / cell)];
const on = rnd() < amount * (0.15 + f * 1.15);
```

これで抜けが塊で発生するようになり、線の一部だけがまとめて薄くなります。粒の大きさ（`cell`）を描画ブロックより十分大きく取るのがコツで、近い値にすると結局また網点に見えます。

## おまけ：紙を替えると組版が変わる

原稿用紙を選んだときは、背景の絵を差し替えるだけでは足りませんでした。**文字の組み方を等幅に切り替える**必要があります。1マスに1文字ずつ、字の幅に関係なく同じ間隔で送り、グリフはマスの中央へ寄せる。

原稿用紙なのに文字が詰まったり空いたりしていると、一目で嘘に見えます。

罫線側にも同じ考え方を入れていて、**罫線は文字の位置を基準に引いています**。紙に固定の罫線を描いてから文字を乗せるのではなく、組み上がった行に合わせて線を並べる。こうするとキャンバスサイズを固定しても行と罫線がずれません。

## まとめ

- 手書きらしさは1文字単位の乱数では出ない。**行の流れ（傾き＋うねり）を先に作る**
- 文字は基準線の**接線角**に乗せる。縦にずらすだけでは足りない
- 行の流れが主、字ごとの揺らぎが従。配分を逆にすると脅迫状に戻る
- シード再現を実用にするには、**描かない文字でも乱数列を同じだけ進める**
- かすれは一様ノイズだと網点になる。粗い濃淡フィールドで確率を変調する
