4択問題を自分で作って、覚えるまで出題するブラウザの暗記ツールを作りました。

公開後、使ってくれた人から一番評価されたのは「正解するほど出題の間隔が空き、間違えた問題は翌日にまた出る」という出題スケジュールでした。この部分は、実装すると60行に満たない小さなモジュールです。ただ、その60行に行き着くまでに捨てた選択肢がいくつかあります。

この記事は、出題スケジュールをどう決めたかの設計メモです。

## 間隔反復とは

間隔反復（Spaced Repetition）とは、覚えた内容を**忘れかけたころに復習する**ように、復習の間隔をだんだん広げていく学習法です。毎日全問を解き直すより少ない回数で、記憶に残せます。

アプリで実装するときの選択肢は、大きく2つあります。

| 方式 | 次の出題日の決め方 | 必要な入力 |
|---|---|---|
| 段階式（ライトナー方式） | 問題ごとの「段」で決まる。正解で1段上がり、不正解で最初の段へ戻る | 正解か不正解か |
| SM-2系（SuperMemo・Ankiの系統） | 問題ごとの「易しさ係数」と前回の間隔から計算する | 思い出しやすさの自己評価（0〜5など） |

ライトナー方式は、ドイツのジャーナリスト、セバスティアン・ライトナーが1972年の著書で紹介した、カードを箱に入れて移していく方法です。SM-2は、ピョートル・ヴォズニャクがSuperMemoのために1987年に作ったアルゴリズムで、Ankiの標準スケジューラのもとにもなっています。

## SM-2を入れなかった理由

最初はSM-2を入れるつもりでした。有名で、実績もあります。やめた理由は、**4択では自己評価が取れない**からです。

SM-2は、回答した後に「すぐ思い出せた」「なんとか思い出せた」「思い出せなかった」のような評価を**学習者自身に**付けてもらい、その評価で易しさ係数を上げ下げします。Ankiで答えを見た後にボタンを押すのがこれです。

4択の場合、ツールが受け取れるのは**どの選択肢を押したか**だけです。

- 正解したけれど、実は消去法で当てただけかもしれない
- 迷わず正解したのかもしれない

この2つは、クリックの結果からは区別できません。区別できない以上、評価は「正解か不正解か」の2値しかありません。2値の入力でSM-2を動かすと、易しさ係数が上下に振れるだけで、SM-2の細かさは生かせません。

回答のたびに「どれくらい自信がありましたか？」と聞く案も考えました。でも、4択を1問解くたびに評価ボタンをもう1回押すのは、作業として重すぎます。暗記ツールは毎日開いてもらってこそ意味があるので、**1問1クリックで終わること**を優先しました。

入力が2値なら、2値で素直に動くライトナー方式のほうが合います。

## 間隔は6段にした

段ごとの間隔は次のようにしました。

| 今の段 | 正解したときの次の出題 | 正解後の段 |
|---|---|---|
| Lv0（新規・間違えた問題） | 翌日 | Lv1 |
| Lv1 | 3日後 | Lv2 |
| Lv2 | 1週間後 | Lv3 |
| Lv3 | 2週間後 | Lv4 |
| Lv4 | 1か月後 | Lv5（覚えた） |
| Lv5 | 3か月後 | Lv5のまま |

不正解は、どの段にいても **Lv0に戻して翌日** に出します。

コードにすると、間隔は配列1本です。

```js
export const MAX_LEVEL = 5;
export const INTERVALS = [1, 3, 7, 14, 30, 90];
```

`INTERVALS[今の段]` が次の出題までの日数です。1・3・7・14・30と、ほぼ倍々に広げています。

段を「覚えた」で止めずに、Lv5でも3か月ごとに出し続けているのは、資格試験の勉強を想定しているからです。試験は数か月先にあることが多く、1か月で「覚えた」扱いにして二度と出さないと、本番前に抜けている問題に気づけません。

## 一番迷ったところ：出題日前に正解したら段を上げるか

このツールには出題モードが3つあります。

- **今日の復習**：出題日が今日以前の問題だけを出す
- **全問**：出題日に関係なく全部出す
- **間違えた問題だけ**：直前の結果から間違えた問題を出す

問題は「全問」モードです。3日後に出す予定の問題を、今日たまたま正解したらどうするか。

素直に考えると「正解したんだから段を上げる」です。でも、こうすると困ったことが起きます。昨日覚えたばかりの問題を全問モードで何回か解くと、**1日で1か月後の段まで上がってしまいます**。直前に見た問題に正解できるのは当たり前で、それは長く覚えている証拠になりません。

間隔反復の効果は、間隔を空けてから思い出せたかを確かめるところにあります。なので、**出題日が来ていない問題は、正解しても段を上げない**ことにしました。

```js
// 回答を反映した新しい問題オブジェクトと、表示用の変化情報を返す
// 出題日が来ていない問題（全問モード）を正解しても、習熟度は先取りで上げない
export function applyAnswer(question, isCorrect, todayYmd) {
  const from = question.level;
  if (!isCorrect) {
    const next = addDays(todayYmd, 1);
    return {
      question: { ...question, level: 0, next, ng: question.ng + 1 },
      info: { from, to: 0, days: 1, advanced: false },
    };
  }
  if (!isDue(question, todayYmd)) {
    return {
      question: { ...question, ok: question.ok + 1 },
      info: { from, to: from, days: null, advanced: false },
    };
  }
  const days = INTERVALS[Math.min(from, MAX_LEVEL)];
  const to = Math.min(from + 1, MAX_LEVEL);
  return {
    question: { ...question, level: to, next: addDays(todayYmd, days), ok: question.ok + 1 },
    info: { from, to, days, advanced: true },
  };
}
```

一方で、**不正解は出題日前でもLv0に戻します**。上げるのは慎重に、下げるのはすぐに、という非対称にしています。予定より前に解いて間違えたなら、その時点でもう忘れているということなので、待つ理由がありません。

画面には「Lv2のまま（出題日前の問題なので習熟度は上げません）」と理由を出しています。黙って据え置くと、正解したのに段が上がらないのはバグに見えるからです。

## 日付は文字列で持つ

次の出題日は `Date` ではなく、端末のローカル日付で作った `"2026-10-06"` 形式の文字列で持っています。

```js
export function isDue(question, todayYmd) {
  return !question.next || question.next <= todayYmd;
}
```

文字列にした理由は2つあります。

1. **「日」単位で比べたい**から。タイムスタンプで持つと、昨日の23時に解いた問題の「翌日」が今日の23時になり、朝に開いても出てきません。人の感覚の「翌日」は日付が変わった時点です
2. **CSVにそのまま書ける**から。問題と学習記録はユーザーのPCにファイルで保存する設計なので、Excelで開いても読める形にしておきたかった

`YYYY-MM-DD` はゼロ埋めしてあれば、文字列の大小比較がそのまま日付の前後比較になります。出題日が空の問題（CSVで作ったばかりの問題）は、すぐに出題します。

日付の足し算は、`Date` に日数を足してローカル日付に戻すだけです。月末や年末をまたぐ繰り上がりは `Date` のコンストラクタがやってくれます。

```js
export function addDays(ymd, days) {
  const [y, m, d] = ymd.split('-').map(Number);
  return formatDate(new Date(y, m - 1, d + days));
}
```

## 学習記録をサーバーに置かなかった理由

段と出題日は問題ごとの列として、問題と同じCSV／JSONファイルに書き込みます。

| 問題 | 正解 | 誤答1〜3 | 解説 | 習熟度 | 次の出題日 | 正解数 | 不正解数 |
|---|---|---|---|---|---|---|---|

サーバーに保存しないので、アカウント登録が要りません。問題文や学習記録をサーバーへ送る通信もありません。資格試験の勉強では社内の資料から問題を作る人もいるはずで、それを外に出さなくていいことを優先しました。

Chrome／Edgeでは File System Access API で開いたファイルにそのまま上書き保存し、それ以外のブラウザではダウンロードで保存します。保存し忘れに備えて、作業中の状態はIndexedDBにも自動でバックアップしています。正本はあくまでPC上のファイルです。

ファイルが正本だと、別のPCでも同じファイルを開けば続きから学習できます。同期の仕組みを作らずに済んだのも、この設計にした理由の1つです。

## まとめ

- 4択のように**入力が正解／不正解の2値**しかないなら、SM-2より段階式（ライトナー方式）のほうが合う
- 間隔は配列1本（`[1, 3, 7, 14, 30, 90]`）。「覚えた」後も止めずに3か月ごとに出す
- **出題日前の正解では段を上げない**。直前に見た問題の正解は、覚えている証拠にならない
- 上げるのは慎重に、下げるのはすぐに。不正解はいつでもLv0・翌日
- 出題日はローカル日付の `YYYY-MM-DD` 文字列で持つ。「翌日」を人の感覚に合わせられて、CSVにもそのまま書ける
